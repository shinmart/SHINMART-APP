# CLAUDE.md — SHINMART-APP

Приложение учёта ШИНМАРТ (шины, Астана): продажи, остатки, закупки, расходы,
счета, анализ. Работает с телефона владельца и его отца.
Стек: Google Sheets + Google Apps Script (`google.script.run`), один HTML-файл
интерфейса без сборщика. Позже перенос на свой сервер (Node.js + PostgreSQL),
см. [`docs/code/migration-plan.md`](docs/code/migration-plan.md).

Этот файл читается в каждой задаче, поэтому в нём только то, что нужно
всегда. Остальное лежит в отдельных файлах: их открывают по ссылке.

## Как работать с кодом, не читая всё подряд

1. **Сначала [`docs/code/nav.md`](docs/code/nav.md).** Там сказано, какой
   документ и какой файл нужны под задачу. Файлы большие (`Code.gs` ~1800
   строк, `WebApp.gs` ~1400) — целиком не читать.
2. **Искать `grep`-ом по имени функции, читать нужный кусок** (`Read` с
   `offset` и `limit`). Имена публичных методов — в `docs/api/SPEC_APP.md`.
3. **Правила подгружаются сами** из `.claude/rules/` по `paths:`.
4. **Не читать:** `node_modules/`, `.env*`. Уже прочитанный файл повторно не
   открывать, если он не менялся.
5. Перед работой — свой раздел [`LESSONS.md`](LESSONS.md), не весь файл.

## Структура

```
apps-script/
  Code.gs        # старая таблица: меню, FIFO (recalcFifoForKeys), Kaspi, общие хелперы
  WebApp.gs      # веб-приложение: доступ, продажи, приход, итоги, миграция листов
  Ops.gs         # этап «Деньги»: настройки, роли, счета, вложения, комиссии, слив
  Mirror.gs      # зеркало новых листов в старые ЗАКУПКИ / ПРОДАЖИ
  Index.html     # весь интерфейс (CSS + JS в одном файле)
tests/ops.test.js  # проверка серверной логики на модели таблицы (node)
docs/            # nav, сценарии, контракт методов, git, тесты
LESSONS.md       # уроки из багов
```

Листы данных: `ПРОДАЖИ_ЖУРНАЛ`, `ЗАКУПКИ`, `ОСТАТКИ`, `РАСХОДЫ`,
`НАСТРОЙКИ`, `СЧЕТА`, `ДВИЖЕНИЕ_ДЕНЕГ`, `APP_ЖУРНАЛ`. Подробно —
[`.claude/rules/architecture.md`](.claude/rules/architecture.md).

## Одна ответственность — одно место

- Поток: `Index.html → google.script.run → публичный app*(p) → appGuard_ →
  внутренние функции *_`. Интерфейс не знает про листы, серверный код не
  знает про DOM.
- Каждая операция — **одна строка** в листе (продажа, приход, расход,
  движение денег). Отмена очищает строку и пишет в `APP_ЖУРНАЛ`. Остатки и
  балансы выводятся из этих строк, не хранятся отдельно (так проще
  переехать в базу).
- Права решает **сервер**: роль продавца вычищается в `opsScrub_`, а не
  скрывается кнопкой.
- Общие хелперы `Code.gs` (`SHEETS`, `getHeaderMap`, `resolveCols`,
  `recalcFifoForKeys`, `getSS_`) не копировать, а вызывать.
- Файл больше ~400 строк кода одной темы — повод вынести в новый `.gs`.

## Сначала документ, потом код

```
1. Сценарий → docs/business/<тема>.md       экраны, роли, состояния
2. Контракт → docs/api/SPEC_APP.md          метод, параметры, ответ, ошибки
3. Код      → apps-script/*.gs, Index.html
4. Каталог  → docs/business/features-catalog.md  строка статуса
```

## Проверка

```bash
node tests/ops.test.js     # серверная логика на модели таблицы
node tests/mirror.test.js  # построение строк зеркала
node tests/prodaji-blocks.test.js  # блоки дней старого листа ПРОДАЖИ
```

Интерфейс — открыть `Index.html` в браузере с подставленным
`google.script.run` (см. [`docs/code/testing.md`](docs/code/testing.md)).

## Готово — это когда

1. Тест проходит; для нового серверного метода добавлен сценарий в
   `tests/ops.test.js`.
2. Интерфейс открыт в браузере: загрузка, пусто, ошибка, ширина телефона
   (390 px). **Если проверял только на модели — сказать прямо**
   (`LESSONS.md` L-015).
3. Документы обновлены в том же коммите: `nav.md`, `SPEC_APP.md`,
   `features-catalog.md`.
4. Владельцу сказано: какие файлы заменить, нужно ли меню «Подготовить…» и
   **новая версия развёртывания** (`docs/code/deploy.md`).
5. Если чинился баг или владелец поправил — урок в `LESSONS.md`.

## Код и git

- Минимальное изменение, несвязанный код не трогать. Замена в файле — только
  с проверкой `count(old) == 1`, потом `git diff`.
- Формулы в таблицу — только `setFormula` (английский синтаксис); текст с `=`
  через `setValues` запрещён (L-009).
- Запись в кэш не должна ломать уже сделанную запись в таблицу (L-008).
- Реальные почты в публичный репозиторий не коммитить (L-014); секреты не
  коммитить.
- Коммит — одна законченная мысль, заголовок до ~72 символов.
  Подробно — [`docs/code/git.md`](docs/code/git.md), баги —
  [`docs/code/bugfix.md`](docs/code/bugfix.md).

# Как писать документы, чтобы их читали дёшево

Документация нужна агенту, чтобы **не читать код**. Читать её должно быть
дешевле, чем просканировать папку, иначе она не нужна.

## Принципы

1. **Одна тема — один файл.** Правило живёт в одном месте, остальные на
   него ссылаются (`см. architecture.md § Запреты`) и не пересказывают его.
2. **Ссылка, а не `@импорт`.** `@file` в `CLAUDE.md` подгружает файл в
   каждую задачу. Обычная ссылка `[текст](путь)` открывается только тогда,
   когда она нужна.
3. **Короткие файлы.** `CLAUDE.md` — до ~150 строк, правило — до ~150, сценарий
   — до ~200. Длиннее — делить по темам.
4. **Удобно читать кусками.** Заголовки `##` с ясными именами, таблицы
   вместо абзацев, ссылки вида `файл § Раздел`, чтобы открыть только
   раздел.
5. **Пути и имена — точные.** `apps-script/Ops.gs`, а не
   «функция счетов где-то в скриптах». Точный путь избавляет от поиска.
6. **Факты, а не история.** Документ описывает, как устроено сейчас. Почему
   так решили — в теле коммита. Устаревшее удалять, не зачёркивать.
7. **Правило, которое проверяет машина, — тестом или линтером**, а не
   абзацем.

## Что где лежит

| Документ | Отвечает на вопрос | Когда обновлять |
|----------|--------------------|-----------------|
| `CLAUDE.md` | как здесь работать вообще | меняется схема или процесс |
| `docs/code/nav.md` | какой файл открыть под задачу | новый файл, маршрут, фича |
| `.claude/rules/*.md` | как писать код в этой области | новое правило или урок поднят до правила |
| `docs/business/<тема>.md` | что делает пользователь, экраны, состояния | меняется сценарий |
| `docs/api/SPEC_*.md` | какой запрос и какой JSON | меняется контракт |
| `docs/business/features-catalog.md` | что готово, что в работе | фича сменила статус |
| `docs/code/ui/components-map.md` | какой компонент уже есть | добавлен или удалён компонент кита |
| `LESSONS.md` | на какие грабли уже наступали | исправлен баг, поправка владельца |

## Новое правило для `.claude/rules/`

Файл `<тема>.md` с полем `paths:` (glob файлов, при работе с которыми
правило нужно). Без `paths:` правило загружается **в каждую задачу**, поэтому
так делать только для того, что действительно нужно всегда.

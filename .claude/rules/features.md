# Как собирать функцию

## Порядок

1. **Сценарий** — `docs/business/<тема>.md`: экраны, роли, состояния
   (загрузка, пусто, ошибка, нет прав).
2. **Контракт** — строка метода в `docs/api/SPEC_APP.md`: параметры, ответ,
   ошибки, кто может вызвать.
3. **Сервер** — публичный `app…(p)` через `appGuard_` + внутренние `…_`.
4. **Тест** — сценарий в `tests/ops.test.js`: нормальный путь, отказ для
   продавца, дубль (`reqId`), отмена.
5. **Интерфейс** — секция в `Index.html`; вызов только через `run(имя, p)`.
6. **Проверка** в браузере на телефонной ширине.
7. Строка в `docs/business/features-catalog.md` и `docs/code/nav.md`.
8. Сообщение владельцу: что заменить, нужен ли пункт меню, новая версия
   развёртывания.

## Состояния экрана

Каждый экран показывает: загрузка («Загружаю…»), пусто (`.empty`), ошибка
(`.banner` с текстом причины), данные. Кнопка записи блокируется на время
запроса и возвращается в исходный вид.

## Скорость

- Частая операция (продажа) — оптимистично в интерфейсе, на сервере только
  запись; тяжёлый пересчёт вторым запросом (L-006).
- Один `google.script.run` ≈ 1 с: не делать цепочки из нескольких запросов,
  если хватит одного.
- Данные, которые телефон всё равно скачивает, отдавать одним ответом.
